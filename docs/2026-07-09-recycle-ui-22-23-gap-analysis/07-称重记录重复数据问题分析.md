# 称重结束后未完成项出现重复数据问题分析

> **日期**：2026-07-10
> **问题现象**：Recycle 称重后出现两条相同的记录，刷新后重复消失
> **严重度**：高（数据重复，用户体验差）
> **相关日志**：`MaterialClient.Recycle-20260710.log` 第 62、66 行

---

## 问题现象

### 用户描述
- 只要在称重结束后就会出现两条记录
- 在没有匹配的情况下，以前没有这个问题
- 刷新后重复数据会消失

### 日志证据
从 `MaterialClient.Recycle-20260710.log` 可以看到：

```log
2026-07-10 08:56:56.323 +08:00 [INF] Converting WaitingForStability -> WeightStabilized: weight=2.770t, stability.IsStable=true
2026-07-10 08:56:56.402 +08:00 [INF] Converting WaitingForStability -> WeightStabilized: weight=2.770t, stability.IsStable=true
2026-07-10 08:56:56.565 +08:00 [INF] Created weighing record successfully, ID: 5, Weight: 2.76t, PlateNumber: None, DeliveryType: "Receiving"
2026-07-10 08:56:56.566 +08:00 [INF] Last created weighing record ID set to 5
2026-07-10 08:56:56.568 +08:00 [INF] 接收到新称重记录创建事件, ID: 5
```

**关键发现**：
- 第 62 行和第 66 行，**相同的稳定状态转换触发了两次**
- `Converting WaitingForStability -> WeightStabilized` 出现两次，完全相同的参数
- 每次状态转换都会创建称重记录，导致重复

---

## 根本原因分析

### 问题定位

**文件**：`MaterialClient.Common/Services/AttendedWeighing/AttendedWeighingService.cs`

**代码位置**：第 224-230 行

```csharp
// Subscribe to combined status stream
var combinedStream = statusStream
    .CombineLatest(
        weightStream,
        stabilityStream,
        (status, weight, stability) => (Status: status, Weight: weight, Stability: stability))
    .DistinctUntilChanged(t => t.Status);  // ⚠️ 只去重了 Status 字段
```

**问题**：`DistinctUntilChanged` 只对 `Status` 字段进行去重，没有考虑 `Stability.IsStable` 字段的变化。

### 去重机制失效的原理

当称重稳定检测完成后：

1. **第一次转换**：
   - `Status`: `WaitingForStability` → `WeightStabilized`
   - `Stability.IsStable`: `true`
   - 触发第 399-410 行的称重记录创建逻辑

2. **第二次转换**（问题所在）：
   - `Status`: `WeightStabilized` → `WeightStabilized`（不变）
   - `Stability.IsStable`: `true` → `true`（不变，但 Stability 对象可能重新创建）
   - 由于 `Status` 变化时已发布事件，`Stability` 后续变化导致 `CombineLatest` 再次触发
   - 触发第 417-426 行的**备份检查逻辑**

### 双重创建逻辑

在 `ProcessWeightChangeAsync` 方法中，有两处会创建称重记录：

```csharp
// 位置 1：第 399-410 行 - 状态转换时创建
if (previousStatus == AttendedWeighingStatus.WaitingStability &&
    newStatus == AttendedWeighingStatus.WeightStabilized &&
    _stateManager.GetLastCreatedWeighingRecordId() == null)
{
    EnqueueAsyncOperation(async () => await OnWeightStabilizedAsync(weightToUse));
}

// 位置 2：第 417-426 行 - 备份检查创建
if (newStatus == AttendedWeighingStatus.WeightStabilized &&
    stability.IsStable &&
    _stateManager.GetLastCreatedWeighingRecordId() == null)
{
    EnqueueAsyncOperation(async () => await OnWeightStabilizedAsync(weightToUse));
}
```

**双重触发的原因**：
- 第一次：`Status` 变化 → 触发位置 1
- 第二次：`Stability` 对象变化 → `CombineLatest` 再次触发 → 触发位置 2

### 为什么刷新后重复消失

1. 称重记录创建后，`WeighingRecordCreatedEventData` 事件发布
2. 订阅者调用 `RefreshAsync()` 刷新列表
3. **第二次创建的记录**在数据库中（两条记录）
4. 但由于状态机设置 `_stateManager.GetLastCreatedWeighingRecordId()` 为已创建的 ID
5. 用户手动刷新时，列表从数据库重新查询，两条记录都存在
6. **这里用户的描述可能有误**，实际上刷新后重复记录**不会消失**，而是需要手动删除其中一条

## 修复方案

### 方案 1：修复去重逻辑（推荐）

**文件**：`MaterialClient.Common/Services/AttendedWeighing/AttendedWeighingService.cs`

**修改位置**：第 230 行

```csharp
// 修改前
.DistinctUntilChanged(t => t.Status);

// 修改后
.DistinctUntilChanged(t => new { t.Status, t.Stability.IsStable });
```

**优点**：
- 从源头避免重复触发
- 不影响现有业务逻辑
- 符合响应式编程的最佳实践

**缺点**：
- 需要测试响应时间是否受影响

### 方案 2：删除备份检查逻辑（不推荐）

**文件**：`MaterialClient.Common/Services/AttendedWeighing/AttendedWeighingService.cs`

**修改位置**：第 417-426 行

删除或注释掉备份检查逻辑：

```csharp
// Backup check: if already WeightStabilized but no record created yet
// if (newStatus == AttendedWeighingStatus.WeightStabilized &&
//     stability.IsStable &&
//     _stateManager.GetLastCreatedWeighingRecordId() == null)
// {
//     var weightToUse = stability.StableWeight ?? weight;
//     _logger.LogInformation("Weight stabilized (backup check), stable weight: {Weight}t", weightToUse);
//
//     EnqueueAsyncOperation(async () => await OnWeightStabilizedAsync(weightToUse));
// }
```

**缺点**：
- 备份检查逻辑是为了防止极端情况下称重记录未创建的风险
- 删除后可能引入新的 bug

### 方案 3：在创建前增加去重检查

**文件**：`MaterialClient.Common/Services/AttendedWeighing/WeighingRecordService.cs`

**修改位置**：在 `CreateWeighingRecordAsync` 方法开始处

```csharp
[UnitOfWork]
public async Task CreateWeighingRecordAsync(decimal weight, List<string> photoPaths, IWeighingStateManager stateManager)
{
    // 防止重复创建：检查最后创建的记录ID
    var lastCreatedId = stateManager.GetLastCreatedWeighingRecordId();
    if (lastCreatedId != null)
    {
        var lastRecord = await _weighingRecordRepository.FirstOrDefaultAsync(r => r.Id == lastCreatedId);
        if (lastRecord != null && Math.Abs((lastRecord.TotalWeight - weight)) < 0.1m)
        {
            _logger.LogWarning(
                "Skipping duplicate weighing record creation: lastId={LastId}, lastWeight={LastWeight}t, currentWeight={Weight}t",
                lastCreatedId, lastRecord.TotalWeight, weight);
            return lastRecord; // 返回已存在的记录
        }
    }

    // 原有逻辑...
}
```

**优点**：
- 在数据库层增加最后一道防线
- 可以容忍其他地方的重复触发

**缺点**：
- 治标不治本，问题根源仍然存在
- 可能掩盖其他潜在问题

---

## 推荐实施步骤

1. **优先采用方案 1**（修复去重逻辑）
   - 修改第 230 行的 `DistinctUntilChanged`
   - 测试称重流程，确保只创建一条记录

2. **如果方案 1 不足以解决问题，结合方案 3**
   - 在 `WeighingRecordService.CreateWeighingRecordAsync` 中增加去重检查
   - 形成双重保障

3. **避免采用方案 2**
   - 保留备份检查逻辑，除非能证明其完全冗余

## 验证方法

修复后，通过以下步骤验证：

1. **单次称重测试**
   - 清空测试数据库
   - 执行一次完整的称重流程
   - 检查数据库中的 `WeighingRecord` 表，确保只有一条记录

2. **日志检查**
   - 查看日志中 `Converting WaitingForStability -> WeightStabilized` 只出现一次
   - `Created weighing record successfully` 只出现一次

3. **界面检查**
   - 称重完成后，未完成项列表中只有一条记录
   - 不需要手动刷新
