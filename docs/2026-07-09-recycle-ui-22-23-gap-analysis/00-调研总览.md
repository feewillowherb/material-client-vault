## 调研问题

`MaterialClient.Recycle`（5020）复用 SolidWaste 称重 UI（`SolidWasteModeFormView` + `AttendedWeighingDetailView` + `AttendedWeighingWindow`）。主要对接市平台：

| 接口 | 业务 | 端点 |
|------|------|------|
| **§2.2** | 发料（成品销售车次） | `POST .../productTransportRecord/v1/addBatch` |
| **§2.3** | 收料（物料进场车次） | `POST .../materialTransportRecord/v1/addBatch` |

**核心问题**：当前页面是否满足 §2.2 与 §2.3 的数据采集需求？同步层是否完整？

---

## 结论摘要

| 维度 | §2.2 发料 | §2.3 收料 |
|------|----------|----------|
| **UI 数据采集** | 基本够用（缺单价/合同等可选项） | 基本够用（缺单价等可选项） |
| **收/发料 UI 区分** | ✅ 有 `DeliveryType` 切换 | ✅ 同上 |
| **字段语义对齐** | 出场时间/出场照基本合理 | 进场时间/进场照**未对齐** |
| **上报实现** | 有 `RecycleDataSyncService`，但不完整 | **无** §2.3 客户端 |
| **按类型分流** | ❌ 收料记录也会进 §2.2 | ❌ |

**一句话**：表单页作为**业务录入**大体可用；作为**完整对接 §2.2 + §2.3** 不满足，缺口主要在**同步层**（分流、单位、时间/照片语义、字段映射），而非单纯 XAML。

---

## 分析范围（三块 UI 须合并看待）

`SolidWasteModeFormView.axaml` 仅是表单区，完整称重界面包含：

| 组件 | 路径 | 职责 |
|------|------|------|
| 收/发料切换 | `AttendedWeighingWindow.axaml` | `DeliveryType`：收料 / 发料 |
| 重量与时间 | `AttendedWeighingDetailView.axaml` | 毛/皮/净重、进场/出场时间、操作员 |
| 业务表单 | `SolidWasteModeFormView.axaml` | 车牌、供应商、材料、联单、镇街、类型、备注 |
| ViewModel | `SolidWasteWeighingDetailViewModel` | Recycle 与 SolidWaste 共用（`AttendedWeighingViewModel` 分支） |

---

## 业务与接口映射

```
收料 (DeliveryType.Receiving)  →  §2.3 materialTransportRecord
发料 (DeliveryType.Sending)      →  §2.2 productTransportRecord
```

当前 `RecycleDataSyncService` **仅调用 §2.2**，且**不读取** `WeighingRecord.DeliveryType` 分流。
