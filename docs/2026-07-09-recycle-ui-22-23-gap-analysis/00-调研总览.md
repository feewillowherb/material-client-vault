## 设计定稿（已确认）

| # | 决策 |
|---|------|
| 1 | 本文件夹为 **Recycle 资源化利用厂对接综合设计**，非单一缺口清单 |
| 2 | **`dataNo`**：Recycle 权威来源为 **`Waybill.OrderNo`**（不使用联单编号 UI） |
| 3 | **照片**：沿用系统 **`UnmatchedEntryPhoto`** 链路；UI 进/出场格为称重**进/出场语境**；**§2.2 / §2.3 API 图片均取进场侧图片**（`EntryPhoto` / `UnmatchedEntryPhoto` / 匹配前 LPR 双附件中的进场展示位） |
| 4 | **重量**：UI **统一按吨显示**；上报市平台时 **按各接口文档单位**转换（§2.2 吨、§2.3 kg），与地磅原始单位无关 |
| 5 | 本文档 **不展开 OpenSpec 实施排期**；实现时另建变更即可 |
| 6 | Recycle **不使用 SolidWaste 领域 API**（如 `UpdateSolidWasteModeAsync`）；需 **独立的 Recycle 领域 Service/API** |
| 7 | LPR 双附件 **无删除/替换**专项需求（忽略） |
| 8 | **`carrierCompanyName`**（§2.2 / §2.3）：**始终**取 **`ProviderId` → `Provider.ProviderName`** |
| 9 | **同步前置条件**：仅 **运单已完成**（Waybill 完成态）的记录参与市平台上报 |

## 范围与目标

`MaterialClient.Recycle`（5020）对接市平台 **§2.2 发料**、**§2.3 收料**；称重 UI 含独立表单（[05](./05-Recycle独立表单页面.md)）、LPR 无相机方案（[04](./04-仅有Lpr设备方案.md)）、同步层分流与映射（[01](./01-字段对照-22发料.md)、[02](./02-字段对照-23收料.md)）。

| 接口 | 业务 | 端点 |
|------|------|------|
| **§2.2** | 发料 | `POST .../productTransportRecord/v1/addBatch` |
| **§2.3** | 收料 | `POST .../materialTransportRecord/v1/addBatch` |

---

## 结论摘要

| 维度 | §2.2 发料 | §2.3 收料 |
|------|----------|----------|
| **UI 采集** | `RecycleModeFormView` + 父视图 | 同上 |
| **收/发分流** | `DeliveryType.Sending` | `DeliveryType.Receiving` |
| **同步实现** | 目标：`RecycleDataSyncService` 分支 | 目标：§2.3 客户端 + Mapper |
| **上报门槛** | 运单已完成 | 运单已完成 |

**当前代码**：仍共用 SolidWaste 表单/VM，同步仅 §2.2 且未按收/发分流——见 [03-缺口与后续建议.md](./03-缺口与后续建议.md)「相对设计的差距」。

## UI 组成

| 组件 | 目标 | 职责 |
|------|------|------|
| 收/发切换 | `AttendedWeighingWindow` | `DeliveryType` |
| 重量/时间 | `AttendedWeighingDetailView` | 毛/皮/净重（**吨**）、进/出场时间 |
| 业务表单 | **`RecycleModeFormView`** | 车牌、供应商、材料、备注（无联单/镇街/类型） |
| 详情 VM | **`RecycleWeighingDetailViewModel`** | Recycle 领域保存/完成 |

```

```
