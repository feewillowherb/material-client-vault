# §2.3 收料（物料进场车次）字段对照

> 接口：`POST /dataCenter/resourcePlace/materialTransportRecord/v1/addBatch`  
> 文档：[§2.3](../../../MaterialMonospec/docs/SyncDoc/杭州市资源化利用厂数据接入接口V1.0.md#23-物料进场车次数据批量新增接口)  
> 适用业务：`DeliveryType.Receiving`（收料）

---

## 必填字段

| 接口字段 | 类型 | UI / 数据来源 | 持久化 | 同步层（当前） | 状态 |
|----------|------|--------------|--------|---------------|------|

| `pointNumber` | String | 配置 | — | 无 §2.3 实现 | ❌ |
| `carNo` | String | 车牌号 | `PlateNumber` | 无 §2.3 实现 | ❌ |
| `materialName` | String | 材料名称 | `Material.Name` | 无 §2.3 实现 | ⚠️ UI 有，无 API |
| `netWeight` | BigDecimal（**kg**） | 父视图净重 | `Waybill.OrderGoodsWeight` | 无 §2.3 实现 | ⚠️ **单位与 §2.2 不同**（§2.3 为 kg，不应 ÷1000） |
| `inTime` | String | 父视图「进场时间」 | `Waybill.JoinTime` | 当前同步用 `outTime`（§2.2） | ❌ 语义错误 |

## 收料称重语义

收料流程（`DeliveryType.Receiving`）：

- 进场（满车）→ 毛重
- 出场（空车）→ 皮重
- 净重 = 进场毛重 − 出场皮重

对应 API：

- **时间**：`inTime` = `Waybill.JoinTime`（进场）
- **照片**：`inPhoto` = `AttachType.EntryPhoto`（及必要时 Lpr 等）
- **重量**：文档单位为 **kg**，与 §2.2 的「吨」不同

---

## 附件类型对照

| AttachType | 说明 | §2.2 `outPhotos` | §2.3 `inPhoto` |
|------------|------|------------------|----------------|
| `EntryPhoto` (1) | 进场照片 | 不适用 | ✅ 首选 |
| `ExitPhoto` (2) | 出场照片 | ✅ 首选 | 不适用 |
| `Lpr` (5) | 车牌识别 | 当前同步包含 | 视业务 |
| `UrbanPhoto` (6) | 城管抓拍 | 当前同步包含 | 视业务 |

当前 `RecycleDataSyncService.BuildOutPhotosBase64Async` 仅筛选 `ExitPhoto` / `Lpr` / `UrbanPhoto`，**不适合** §2.3 收料。

## §2.3 专项结论

| 项 | 状态 |
|----|------|
| §2.3 Refit API / DTO | ❌ 代码库不存在 `materialTransportRecord` |
| 按 `DeliveryType.Receiving` 分流 | ❌ |
| UI 采集能力 | ✅ 车牌、物料、重量、进场时间可采 |
| 完成校验（镇街/联单） | SolidWaste 规则；Recycle 独立表单已移除相关字段 |

**收料记录在现有 Recycle 同步下会被误送入 §2.2**，属于功能性缺陷，需在后续变更中修复。
