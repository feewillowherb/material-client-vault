# AccessCode 与 MachineCode 分离解决方案

> **文档创建日期**：2026-06-24  
> **前置文档**：[00-问题分析.md](./00-问题分析.md)  
> **关联 EPIC**：[2026-06-23-baseplatform-auth-solution](../2026-06-23-baseplatform-auth-solution/00-EPIC-项目改动总览.md)（已按本文 `AccessCode` 语义对齐）  
> **状态**：方案已定（待实施）

> **语义约定（已定）**  
> - 原 DTO / UrbanManagement 中的 **`BuildLicenseNo` 命名语义错误**；其业务含义实为 **城管接入码**，统一正名为 **`AccessCode`**。  
> - 与 `JC_Project.ShigongCerNo`（施工许可证号）**无关**，不参与城管同步链路。  
> - **`FdBuildLicenseNo`** 仍为凡东 MD5 对接码，命名保留，与 `AccessCode` 不同。

---

## 1. 方案结论（摘要）

| 决策项 | 结论 |
|--------|------|
| 接入码 | **`JC_ProductAuthority.AccessCode`**（运营授权页维护）；发版后手工补录，不自动洗历史 `MachineCode` |
| 设备码 | **`JC_ProductAuthority.MachineCode`** 仅表示机器码；客户端 `SetCorpAuthMachineCode` 回写 |
| 原 `BuildLicenseNo` | **废弃域内语义**；BasePlatform DTO、UrbanManagement 实体/JWT 统一改为 **`AccessCode`** |
| 政府 HTTP 出站 | 协议字段仍可叫 `buildLicenseNo`，**值 = `AccessCode`**（协议名 ≠ 域内名） |
| `FdBuildLicenseNo` | **保持** `MD5(ProId + "findongCode")`，双码校验不变 |
| `ShigongCerNo` | **不纳入** 本方案 |

## 2. 目标语义（修复后）

```
┌──────────────────────────────────────────────────────────────────┐
│ 概念           │ 域内字段名      │ 存储位置                      │
├────────────────┼─────────────────┼───────────────────────────────┤
│ 接入码         │ AccessCode      │ JC_ProductAuthority.AccessCode│
│ (城管对接码)   │                 │ 运营授权页录入                │
├────────────────┼─────────────────┼───────────────────────────────┤
│ 机器码         │ MachineCode     │ JC_ProductAuthority.MachineCode│
│                │                 │ 客户端 API 回写               │
├────────────────┼─────────────────┼───────────────────────────────┤
│ 凡东对接码     │ FdBuildLicenseNo│ 不落库，API/JWT 实时计算      │
│                │                 │ MD5(ProId+"findongCode")      │
└──────────────────────────────────────────────────────────────────┘
```

**命名对照（跨系统）**：

| 层级 | 旧（错误） | 新（正确） |
|------|-----------|-----------|
| BasePlatform PublicApi DTO | `BuildLicenseNo` | **`AccessCode`** |
| UrbanManagement `GovProject` | `BuildLicenseNo` | **`AccessCode`** |
| JWT / 授权文件 Claims | `buildLicenseNo` | **`accessCode`** |
| 政府平台 JSON（出站） | `buildLicenseNo` | 字段名可保留；**值 = AccessCode** |

**JWT Claims（与 EPIC 对齐，修正后）**：

```json
{
  "proId": "...",
  "accessCode": "<接入码>",
  "fdBuildLicenseNo": "<MD5>",
  "machineCode": "<设备机器码>"
}
```

## 3. 根因与产品差异（授权 UI）

`ProjectAuthAdd.cshtml` / `CompanyAuthAdd.cshtml` 对同一列 `MachineCode` 按产品呈现不同标签：

| ProductCode | 产品 | UI 标签 | 当前写入 | 修复后 |
|-------------|------|---------|----------|--------|
| 5000 | MaterialClient | 机器码 | 客户端回写，页面只读 | 不变 |
| 5001 | MaterialDxlt（城管地磅） | 接入码 | 运营写入 `MachineCode` | **`AccessCode`（可编辑）** + **`MachineCode`（可编辑）** |
| 5010 | SolidWasteWeightClient | 接入码 | 同上 | 同 5001（两字段均可编辑） |

混用后果：

1. PublicApi 将接入码写入 DTO 的 **`BuildLicenseNo`**（命名与来源均错）；
2. UrbanManagement 同步后 `GovProject.BuildLicenseNo` 存的是接入码或机器码，语义混乱；
3. 新客户端绑定 `MachineCode` 会覆盖接入码，或无法绑定设备码。

## 4. 数据层改造（BasePlatform）

**策略**：仅新增 `AccessCode` 列；**不**批量修改现有 `MachineCode`。历史接入码由运营在授权页手工维护（见 [02](./02-BasePlatform-AccessCode分列与ListProjects拟稿提案.md) §4.6）。

### 4.1 新增 `AccessCode`

```sql
-- forward-01-ddl-add-accesscode.sql（幂等，见 02 §4.2）
IF NOT EXISTS (
    SELECT 1 FROM sys.columns
    WHERE object_id = OBJECT_ID(N'dbo.JC_ProductAuthority')
      AND name = N'AccessCode'
)
    ALTER TABLE dbo.JC_ProductAuthority
    ADD AccessCode NVARCHAR(200) NULL;
```

```csharp
/// <summary>城管/平台接入码（运营录入，ProductCode 5001/5010 等）</summary>
public string? AccessCode { get; set; }
```

### 4.2 历史数据

**不做** SQL 自动迁移。发版后运营在授权后台为各项目填写 `AccessCode`；`MachineCode` 保持原值，由运营视情况修正。

## 5. PublicApi 改造

> **破坏性变更**：UrbanManagement **尚未上线**，PublicApi `ListProjects` **直接删除** `buildLicenseNo`，不保留兼容别名或配置开关。

### 5.1 `ProjectCatalogItemDto`（移除错误字段）

```csharp
public class ProjectCatalogItemDto
{

    public string ProName { get; set; } = string.Empty;
    public int ProductCode { get; set; }
    public string ProAddress { get; set; } = string.Empty;
    public string ShigongUnitName { get; set; } = string.Empty;

    /// <summary>城管接入码（可控可空字符串，来自 JC_ProductAuthority.AccessCode）</summary>
    public string? AccessCode { get; set; }

    /// <summary>凡东对接码（计算字段，非库表直出）</summary>
    public string FdBuildLicenseNo { get; set; } = string.Empty;

    /// <summary>设备机器码（可控可空字符串，来自 JC_ProductAuthority.MachineCode）</summary>
    public string? MachineCode { get; set; }

    public DateTime? AuthEndTime { get; set; }

    // 已删除：BuildLicenseNo（不保留 Obsolete 别名；Urban 未上线，PublicApi 允许破坏性变更）
}
```

### 5.2 `ListProjects` 映射

```csharp
AccessCode       = authority.AccessCode,
FdBuildLicenseNo = CommonHelper.IoTPwdMD5(parsedProId, "findongCode"),
MachineCode      = authority.MachineCode,
```

**删除**原逻辑：`BuildLicenseNo = authority.MachineCode`。

### 5.3 筛选条件

```csharp
.Where(a => a.ProductCode == TargetProductCode
            && a.DeleteStatus == 0
            && a.AuthStatus == 1
            && !string.IsNullOrEmpty(a.AccessCode))
```

不再以 `MachineCode` 非空作为准入条件。

## 7. UrbanManagement 语义对齐

### 7.1 实体 `GovProject` 字段重命名

| 旧字段 | 新字段 | 说明 |
|--------|--------|------|
| `BuildLicenseNo` | **`AccessCode`** | 城管接入码；与 BasePlatform 一致 |
| `FdBuildLicenseNo` | `FdBuildLicenseNo` | 不变 |
| （新增） | **`MachineCode`** | 设备机器码（可选，来自 PublicApi） |

```csharp
public class GovProject
{
    public Guid Id { get; set; }
    public string ProName { get; set; } = string.Empty;

    /// <summary>城管接入码（原 BuildLicenseNo，语义已纠正）</summary>
    public string AccessCode { get; set; } = string.Empty;

    public string FdBuildLicenseNo { get; set; } = string.Empty;
    public string? MachineCode { get; set; }
    // ...
}
```

EF 迁移：`BuildLicenseNo` 列重命名为 `AccessCode`，或新列 + 数据拷贝后删旧列。

### 7.2 `GovProjectPullBackgroundWorker`

```csharp
var entities = items.Select(x => new GovProject
{
    Id = x.ProId,
    ProName = x.ProName,
    AccessCode = x.AccessCode,
    FdBuildLicenseNo = x.FdBuildLicenseNo,
    MachineCode = x.MachineCode,
    // ...
}).ToList();
```

**删除**：`BuildLicenseNo = x.BuildLicenseNo` 或从 DTO 错误字段映射。

### 7.3 脏数据修复

历史 `Gov_Project.BuildLicenseNo` 中可能是接入码或机器码：

```sql
-- 以 BasePlatform 拉取结果为准刷新
UPDATE g
SET g.AccessCode = src.AccessCode,
    g.FdBuildLicenseNo = src.FdBuildLicenseNo,
    g.MachineCode = src.MachineCode
FROM Gov_Project g
JOIN <PublicApi 同步结果> src ON g.Id = src.ProId;
```

若先做列重命名：

```sql
-- 1. 重命名列（SQLite / SQL Server 语法按环境调整）
-- 2. 再按 PublicApi 全量校正 AccessCode
```

**识别脏数据**：

- `AccessCode`（原 `BuildLicenseNo`）与 `MachineCode` 相同 → 可能仍为混用记录；
- `AccessCode` 呈 MD5 形态 → 可能误存了 `FdBuildLicenseNo`。

### 7.4 政府平台出站（`GovSyncBackgroundWorker`）

域内用 `AccessCode`，出站映射政府协议：

```csharp
// 政府 JSON 字段名仍为 buildLicenseNo（协议遗留）
payload.buildLicenseNo = govProject.AccessCode;
payload.fdBuildLicenseNo = govProject.FdBuildLicenseNo;
```

与旧萧山行为一致：`buildLicenseNo` = **场地/接入标识**，不是施工许可证号。

### 7.5 客户端 / 验证

- `LicenseInfo`、JWT 校验：主键字段由 `LicenseKey` / `buildLicenseNo` 逐步改为 **`AccessCode`**（或 `LicenseKey` 存 `AccessCode` 值，属性重命名）。
- 按 `FdBuildLicenseNo` 查项目：条件改为 `GovProject.FdBuildLicenseNo == fdBuildLicenseNo`（不变）。
- 按接入码查项目：`GovProject.AccessCode == accessCode`（原 `BuildLicenseNo` 查询全部替换）。

## 8. 待讨论问题 — 决议

### Q1: 正确的数据映射？

**决议**：`AccessCode = authority.AccessCode`。**否决** `BuildLicenseNo = MachineCode`；**不采用** `ShigongCerNo`。

### Q2: `FdBuildLicenseNo`？

**决议**：保持 MD5 算法；与 `AccessCode`、`MachineCode` 三者分列。

### Q3: UrbanManagement 如何修复？

**决议**：`GovProject.BuildLicenseNo` **重命名为 `AccessCode`**；全量/增量拉取后执行对比修复脚本。

### Q4: 政府 payload 里的 `buildLicenseNo`？

**决议**：协议字段名可保留；**语义 = AccessCode（接入码）**，不是施工许可证号。
