# AccessCode 与 MachineCode 混用问题分析

> **文档创建日期**：2026-06-24  
> **问题来源**：BasePlatform.PublicApi ProjectCatalogController 实际代码  
> **状态**：已有解决方案 → [01-解决方案.md](./01-解决方案.md)  
> **关联**：[2026-06-23-baseplatform-auth-solution](../2026-06-23-baseplatform-auth-solution/00-调研总览.md) 授权方案已同步 `AccessCode` 语义

> **语义说明（已定）**  
> 原 PublicApi / UrbanManagement 中的 **`BuildLicenseNo` 字段名语义错误**。其真实业务含义是 **城管接入码**，应统一为 **`AccessCode`**。与 `JC_Project.ShigongCerNo`（施工许可证号）无关。

---

## 1. 问题概述

在 `FdSoft.BasePlatform.PublicApi\Controllers\ProjectCatalogController.cs` 中发现：

```csharp
// 第 119 行 — 接入码误写入名为 BuildLicenseNo 的 DTO 字段
BuildLicenseNo = authority.MachineCode ?? string.Empty,

// 第 120 行
FdBuildLicenseNo = CommonHelper.IoTPwdMD5(parsedProId, "findongCode"),
```

**核心问题**：

1. 5001 产品在授权页录入的 **接入码** 存在 `JC_ProductAuthority.MachineCode` 列（列名也不对）；
2. PublicApi 将其输出到 DTO 的 **`BuildLicenseNo`**（字段名也不对）；
3. UrbanManagement 同步为 `GovProject.BuildLicenseNo`，进一步放大命名与语义错误；
4. 新客户端需要 **独立的 `MachineCode`（设备码）**，与接入码共用一列导致无法绑定。

## 3. 概念定义对比（纠正后）

| 字段 | 语义说明 | 正确来源 |
|------|---------|----------|
| **AccessCode** | 城管/平台 **接入码**（运营在授权页维护，同一项目固定） | `JC_ProductAuthority.AccessCode`（新增列）；历史由运营手工补录，**不** SQL 从 `MachineCode` 迁移 |
| **MachineCode** | 客户端 **设备机器码**（绑定、授权验证） | `JC_ProductAuthority.MachineCode`（仅设备码） |
| ~~FdBuildLicenseNo~~ | ~~凡东 MD5~~ | **已废弃** |
| ~~BuildLicenseNo~~ | ~~施工许可证号~~ | **命名废弃**；原 DTO/Urban 中该名实际存的是接入码 |
| **ShigongCerNo** | 施工许可证号（项目档案） | `JC_Project`；**不参与** 城管同步本链路 |

**关键差异**：

- **AccessCode** 与 **MachineCode** 是不同概念，不得共用一列；
- 旧文档/代码中的 **`BuildLicenseNo` ≈ 应改名为 `AccessCode`**，不是施工许可证号；
- 政府 HTTP 协议里的 `buildLicenseNo` 在旧萧山系统中意为 **场地/接入标识**，出站值应对齐 **AccessCode**（见 [01-解决方案.md](./01-解决方案.md) §7.4）。

## 4. 混用的潜在影响

### 4.1 UrbanManagement 侧

```csharp
// 当前错误映射
var entities = toInsert.Select(x => new GovProject
{
    Id = x.ProId,
    ProName = x.ProName,
    BuildLicenseNo = buildLicenseNo,  // ← 实为接入码或机器码，字段名错误
    FdBuildLicenseNo = fdBuildLicenseNo,
}).ToList();
```

**后果**：

- `GovProject.BuildLicenseNo` 语义与命名双重错误；
- 若值为机器码，政府双码校验与设备绑定均异常；
- 修复方向：`GovProject.AccessCode`，见 [01-解决方案.md](./01-解决方案.md)。

### 4.2 新客户端无法绑定 MachineCode

- 5001 接入码占满 `MachineCode` 列；
- `SetCorpAuthMachineCode` 写入会覆盖接入码，或不写入则无法完成设备授权（见 EPIC）。

### 4.3 业务语义混乱

- 报表/查询按 `BuildLicenseNo` 无法理解真实含义；
- 与 `ShigongCerNo` 混谈会加剧误解（二者无关）。

## 5. 根本原因分析

| 可能原因 | 可能性 | 说明 |
|---------|-------|------|
| **字段命名混淆** | 高 | DTO 用 `BuildLicenseNo`，UI 用「接入码」，库列用 `MachineCode` |
| **临时占位** | 中 | 接入码临时写入 `MachineCode`，PublicApi 再映射到 `BuildLicenseNo` |
| **历史延续** | 高 | 旧萧山 `buildLicenseNo` = 场地标识，被误读为施工许可证号 |

### 5.1 与 ShigongCerNo 的关系

`JCProject.ShigongCerNo` 是项目档案中的施工许可证号，**不是** PublicApi 当前输出的那串值，**也不应**作为本方案中接入码的替代数据源。

---

## 6. FdBuildLicenseNo（已废弃）

原凡东 MD5 对接码 `MD5(ProId + "findongCode")` **不再使用**。新链路仅 **`AccessCode`** + **`MachineCode`**；PublicApi / JWT / 政府出站均 **不**再携带 `fdBuildLicenseNo`。

> 下文代码片段中若仍出现 `FdBuildLicenseNo = CommonHelper.IoTPwdMD5(...)`，描述的是 **改造前** 现网行为，实施时删除。

---

## 7. JCProductAuthority 表结构

当前缺少 `AccessCode` 列；5001 的接入码误写在 `MachineCode`：

```csharp
public string MachineCode { get; set; }  // 5001：实为接入码；5000：设备码
public string AuthToken { get; set; }
// 待增：public string AccessCode { get; set; }
```
