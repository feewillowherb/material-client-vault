## 1. 问题概述

在 `FdSoft.BasePlatform.PublicApi\Controllers\ProjectCatalogController.cs` 中发现以下代码：

```csharp
// 第 119 行
BuildLicenseNo = authority.MachineCode ?? string.Empty,

// 第 120 行
FdBuildLicenseNo = CommonHelper.IoTPwdMD5(parsedProId, "findongCode"),
```

**核心问题**：`BuildLicenseNo`（施工许可证号）被直接赋值为 `MachineCode`（机器码），这两个完全不同概念的值被混用。

## 3. 概念定义对比

| 字段 | 语义说明 | 来源 |
|------|---------|------|
| **MachineCode** | 客户端机器的唯一标识码，用于设备绑定和授权验证 | `JCProductAuthority.MachineCode` |
| **BuildLicenseNo** | 施工许可证号，由建设主管部门颁发的合法施工证明编号 | 应来自 `JCProject.ShigongCerNo` 或业务字段 |
| **FdBuildLicenseNo** | 对接码（凡东系统专用），用于与政府平台对接 | 通过 MD5(ProId + "findongCode") 生成 |

**关键差异**：
- `MachineCode` 是**设备标识**，每个客户端设备不同
- `BuildLicenseNo` 是**项目证件编号**，同一项目固定不变
- 两者是完全不同的业务概念

## 4. 混用的潜在影响

### 4.1 UrbanManagement 侧数据污染

当 UrbanManagement 通过 `GovProjectPullBackgroundWorker` 拉取数据时：

```csharp
// MaterialMonospec 文档中的设计
var entities = toInsert.Select(x => new GovProject
{
    Id = x.ProId,
    ProName = x.ProName,
    BuildLicenseNo = buildLicenseNo,  // ← 这里会得到 MachineCode
    FdBuildLicenseNo = fdBuildLicenseNo,
    // ...
}).ToList();
```

**后果**：
- UrbanManagement.GovProject.BuildLicenseNo 存储的是机器码，而非施工许可证号
- 当 GovSyncBackgroundWorker 上传数据到政府平台时，`buildLicenseNo` 字段会发送机器码

### 4.2 政府平台接口调用异常

根据 `gov-sync-worker` 规范文档，政府 API payload 中的 `buildLicenseNo` 字段应为施工许可证号：

```csharp
// 政府平台 API 字段映射
BuildLicenseNo → buildLicenseNo  // 应该是施工许可证号
```

**风险**：
- 政府平台可能验证施工许可证号格式（如长度、前缀规则）
- 机器码格式可能不符合施工许可证号规范，导致验证失败

### 4.3 业务语义混乱

- **查询困难**：无法通过 BuildLicenseNo 查询真实施工许可证号
- **报表错误**：相关报表会显示机器码而非许可证号
- **审计问题**：审计时无法对应真实的施工许可证

## 5. 根本原因分析

### 5.1 为什么会混用？

可能原因分析：

| 可能原因 | 可能性 | 说明 |
|---------|-------|------|
| **字段命名混淆** | 高 | 开发者误以为 MachineCode 就是施工许可证号 |

## 6. IoTPwdMD5 算法分析

### 6.1 FdBuildLicenseNo 生成逻辑

```csharp
// D:\CodeUp\FdSoft.Common\CommonHelper.cs
public static string IoTPwdMD5(Guid proId, string salt)
{
    string cl = proId.ToString().ToLower() + salt.ToLower();
    // MD5(cl)
    byte[] s = md5.ComputeHash(Encoding.UTF8.GetBytes(cl));
    // 转换为十六进制字符串
    ...
}
```

**ProjectCatalogController 中的调用**：
```csharp
FdBuildLicenseNo = CommonHelper.IoTPwdMD5(parsedProId, "findongCode")
```

**等价于**：
```csharp
FdBuildLicenseNo = MD5(parsedProId.ToString().ToLower() + "findongcode".ToLower())
```

### 6.2 FdBuildLicenseNo 的特点

| 特性 | 说明 |
|-----|------|
| **确定性** | 同一 ProId 总是生成相同的 FdBuildLicenseNo |
| **不可逆** | 无法从 FdBuildLicenseNo 反推出 ProId |
| **固定格式** | 32 位小写十六进制字符串 |
| **业务含义** | 凡东系统对接码，用于政府平台认证 |

## 7. JCProductAuthority 表结构

### 7.1 实际字段

```csharp
// D:\CodeUp\FdSoft.BasePlatform\FdSoft.BasePlatform.Model\Models\BasePlatform\JCProductAuthority.cs
[SugarTable("JC_ProductAuthority")]
public class JCProductAuthority

    public long AuthId { get; set; }              // 主键（自增）
```

### 7.2 MachineCode 字段用途

`JCProductAuthority.MachineCode` 的设计意图：
- 存储客户端设备的机器码
- 用于设备绑定和授权验证
- **不应该**作为施工许可证号使用
