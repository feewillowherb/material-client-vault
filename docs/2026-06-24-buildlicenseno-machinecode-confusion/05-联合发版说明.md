## 2. 两条主线（勿混淆）

| 主线 | 解决什么 | 主文档 |
|------|----------|--------|
| **A. AccessCode 语义** | 接入码与机器码混用、`BuildLicenseNo` 命名错误 | 02 + 04 §AccessCode |
| **B. JWT 签发归属** | 授权文件由 Urban 签发 → 改由 BasePlatform 签发 | 03 + 04 §JWT |

交叉点：新签发的 JWT Claims 必须使用 **`accessCode`**，数据来自 `JC_ProductAuthority.AccessCode` / `GovProject.AccessCode`。

**JWT 产品范围**：**仅 ProductCode `5001`**。`5000`、`5010` 及其它产品 **不** 走 JWT；`SendAuthLicense` / `DownloadAuth` 等行为与现网一致（见 [EPIC](../2026-06-23-baseplatform-auth-solution/00-EPIC-项目改动总览.md)）。

**授权原则**：离线与在线（5001）均以 JWT 为权威；**不实施** `verify` API；在线激活响应须含 **`jwtToken`**。

**前提**：UrbanManagement **尚未上线** → PublicApi `ListProjects` 等接口**允许破坏性变更**（移除 `buildLicenseNo`、不做过渡别名）；Urban 与 PublicApi 按 04 + 02 **同期对接**即可。

```mermaid
flowchart TD
  S1[02: DDL AccessCode + 授权 UI]

  S2 --> S4
```

| 阶段 | 内容 | 可独立上线？ |
|------|------|--------------|
| **P0** | 02：DDL 新增 `AccessCode` 列（无 SQL 洗数） | 是 |

| **P2** | 03：BasePlatform `/api/auth/license-file` 可用 | 可与 P1 并行开发 |
| **P3** | 04：Urban Pull + `GovProject.AccessCode`（读新字段） | 依赖 P1 |
| **P4** | 04：Urban JWT 代理 / 清理私钥 | 依赖 P2、P3 |

**已取消**：原 P5「关闭 `buildLicenseNo` 兼容别名」— Urban 未上线，02 直接删除该字段，无灰度别名阶段。

**MaterialClient.Urban** 公钥验证与 `LicenseInfo` 属性重命名 **不在本系列拟稿范围**（见 EPIC）；P2/P4 须保证 Issuer/Audience/算法与现网一致。

## 5. 回滚原则

| 故障点 | 回滚 |
|--------|------|
| PublicApi 字段变更 | Urban 未上线：回滚 PublicApi 包或与 04 一并回滚 |
| Urban Pull 失败 | 回滚 Urban；BasePlatform 可保留 `AccessCode` 列 |
| JWT 新签发异常 | Urban 临时恢复旧签发（须保留 feature flag 至 P4 验证完成） |
| 数据 / DDL | 回滚应用后执行 `rollback-01-drop-accesscode.sql`（见 02 §4.4） |
