# Urban BasePlatform 授权方案快速参考

> **字段语义**：`AccessCode` = 城管接入码（原错误命名 `BuildLicenseNo`）。详见 [分离方案](../2026-06-24-buildlicenseno-machinecode-confusion/01-解决方案.md)。  
> **JWT（已定）**：**仅 ProductCode `5001`**；离线与在线均以 JWT 为权威；**不实施** `verify` API。详见 [00-EPIC-项目改动总览.md](./00-EPIC-项目改动总览.md)。

## 推荐架构：UrbanManagement 代理

**采用 UrbanManagement 代理方案**：
- MaterialClient.Urban → UrbanManagement → BasePlatform.PublicApi
- GovProject 统一管理 MachineCode
- 简化客户端部署

> **注**：UrbanManagement 通过 BasePlatform.PublicApi 通信，BasePlatform.WebApi 用于 UI 相关操作。JWT 签发 **仅 5001**；`5000` / `5010` 现网不变。

## 核心概念

### 授权类型（5001）

| 类型 | 值 | 描述 | 使用场景 |
|-----|---|------|---------|
| 离线授权 | 0 | 导入 JWT 明文 `.urban` | 网络隔离环境 |
| 在线授权 | 1 | 授权码激活，响应含 `jwtToken` | 有网络环境 |

### 关键组件

| 组件 | 职责 |
|-----|------|
| BasePlatform | **5001** JWT 签发、机器码存储、`DownloadUrbanLicense` |
| MachineCodeProvider | 获取稳定的机器码 |
| StaticLicenseChecker | 启动时 **本地 JWT 验签** |
| OnlineAuthActivator | 授权码在线激活，写入 `LatestJwtToken` |
| ~~OnlineAuthVerifier~~ | ~~定期在线验证~~ — **不实施** |

## 快速流程图

### 离线授权流程（仅 5001）

```
现场人员 → 脚本获取机器码 → BasePlatform 录入 MachineCode → DownloadUrbanLicense
                                              ↓
客户端 ← 导入 .urban ← JWT 明文 ← 写入 LicenseInfo.LatestJwtToken
    ↓
启动：StaticLicenseChecker 本地 JWT 验签（机器码 + 过期）
```

### 在线授权流程（代理模式，仅 5001）

```
管理员 → BasePlatform.WebApi SendAuthLicense → 提供给用户授权码
                                           ↓
客户端 → 输入授权码 + 机器码 → UrbanManagement activate 代理
                                        ↓
BasePlatform activate-urban → 验 Redis + 写 MachineCode + 签发 JWT
    ↓
UrbanManagement 更新 GovProject ← 返回 jwtToken 给客户端
    ↓
客户端写入 LatestJwtToken → 激活成功
```

### ~~在线验证流程~~（不实施）

日常验权由 **本地 JWT 验签** 完成。~~`POST /api/urban/auth/verify`~~ 已废弃。SignalR 可选用于 **JWT 续期**，非启动门禁。

## 关键数据结构

### 授权文件（离线，5001）

JWT 明文 UTF-8，文件扩展名 `.urban`。Claims 含 `machineCode`、`proId`、`authEndDate`、`accessCode` 等（详见 [03-JWT 拟稿](../2026-06-24-buildlicenseno-machinecode-confusion/03-BasePlatform-JWT签发迁移拟稿提案.md)）。

### MaterialClient.Urban LicenseInfo 结构（实际代码）

| 字段 | 类型 | 说明 |
|-----|------|------|
| ProjectId | Guid | 项目ID |
| AuthToken | Guid? | 授权令牌（可选，过渡期） |
| AuthEndTime | DateTime | **授权结束时间** |
| ProName | string? | 项目名称 |
| AccessCode | string? | 城管接入码（原 BuildLicenseNo） |
| MachineCode | string | 机器码 |
| LatestJwtToken | string? | **JWT 权威凭证**（在线激活或离线导入） |

> **说明**：启动验权以 **`LatestJwtToken`** 为准，经 `StaticLicenseChecker` 本地验签。SignalR 推送仅作可选续期。

### BasePlatform JC_ProductAuthority

| 字段 | 说明 |
|-----|------|
| AccessCode | 城管接入码（BasePlatform 授权表 + GovProject） |
| MachineCode | 客户端设备机器码 |
| ProductCode | 产品标识（城管 = **5001**） |
| AuthStatus | 授权状态（0=未授权，1=已授权） |
| AuthToken | 授权令牌（过渡期） |
| AuthEndTime | 授权结束时间 |
| AuthBeginTime | 授权开始时间 |

## 验证规则总结

### 启动时验证（JWT 本地验签，5001）

1. ✅ 从 `LicenseInfo` 读取 **`LatestJwtToken`**
2. ✅ 获取当前机器码
3. ✅ `StaticLicenseChecker` 验签 JWT
4. ✅ Claims 中 `machineCode` 与当前机器码一致
5. ✅ 检查 JWT 过期时间

### ~~在线验证~~（不实施）

~~定期调用 UrbanManagement verify API~~ — 已废弃。

### 失败处理

JWT 验签失败或机器码不匹配 → 提示「授权无效，请联系管理员」→ **关闭程序**

## 常见问题

### Q: 机器码不稳定怎么办？
A: 使用多重硬件特征（CPU、主板、MAC、硬盘），提供机器码重新绑定流程

### Q: SQLite 被篡改怎么办？
A: JWT 由 BasePlatform 私钥签发，篡改 `LatestJwtToken` 无法通过本地验签

### Q: 网络中断怎么办？
A: 启动门禁不依赖网络；已激活设备凭本地 JWT 运行。SignalR 续期为可选

### Q: 授权文件泄露怎么办？
A: JWT 绑定机器码 Claims，其他机器验签失败
