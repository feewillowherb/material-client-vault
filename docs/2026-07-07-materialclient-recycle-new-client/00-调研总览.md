## 关键发现

1. **MaterialClient 采用模块化架构**：`MaterialClient.Common`（共享层）+ 产品特定模块（如 `MaterialClient.Urban`）。新增 `MaterialClient.Recycle` 应遵循同一模式。
2. **ProductCode 体系已建立**：5000（MaterialClient）、5001/5030（MaterialDxlt/城管）、5010（SolidWaste）。5020 为新增，需在 BasePlatform 授权体系、运营后台、PublicApi 等环节注册。
3. **授权模式按产品隔离**：仅 5001 使用 JWT；5000/5010 使用现网 `SendAuthLicense`/`DownloadAuth`。5020 推荐沿用 5010 的非 JWT 模式（现网流程不变）。
4. **数据上报模式可插拔**：MaterialClient.Urban 通过 Refit `IUrbanManagementApi` 上报；SolidWaste 使用 `SynchronizationOrderAsync`（POST `/api/Order/SynchronizationOrder`，`SynchronizationOrderInputDto`）。Recycle 需要新增一个专用接口对接资源化利用厂 API。
5. **已有完整的数据同步基础设施**：称重记录实体、同步状态管理、重试机制、附件体系（`AttachmentFile` + `AttachType`）可复用。
6. **WeighingMode 枚举已确认**：`Standard=0`、`SolidWaste=1`、`UrbanMode=201`。**Recycle=301 不存在**，需在 `MaterialClient.Common/Entities/Enums/WeighingMode.cs` 中新增。
7. **资源化利用厂接口文档已确认**：位于 MaterialMonospec `docs/SyncDoc/杭州市资源化利用厂数据接入接口V1.0.md`，§2.2 端点 POST `/dataCenter/resourcePlace/productTransportRecord/v1/addBatch`，HMAC-SHA256 认证，请求体为 JSON Array，响应 `{ code: 200 }` 判断成功。
8. **SolidWaste 不是独立客户端**：SolidWaste 是 `WeighingMode.SolidWaste = 1` 的业务模式，与 Standard（0）和 UrbanMode（201）共存于 MaterialClient 主程序中，通过模式切换区分行为。

## 证据缺口清单

| 缺口 | 影响 | 建议 |
|------|------|------|
| `WeighingMode` 枚举中无 `Recycle = 301` 成员 | 无法编译使用 WeighingMode.Recycle 的代码 | 在 MaterialMonospec 中新增枚举成员 |
| `ProductCode` 枚举中无 `Recycle = 5020` 成员 | 无法注册 Recycle 产品 | 在 MaterialMonospec 中新增枚举成员 |
| §2.2 接口的 `pointNumber`（资源化利用厂标识）取值来源 | 请求体必填字段，无法确定配置来源 | 需从运营方获取各厂唯一标识 |
| §2.2 接口的 `productName`（成品名称）取值来源 | 请求体必填字段，无法确定映射关系 | 需确认称重记录中是否有对应字段 |
| §2.2 接口的 HMAC-SHA256 签名密钥（accessKey）获取方式 | 无法构造认证 Header | 需从平台方获取 accessKey + secretKey |
