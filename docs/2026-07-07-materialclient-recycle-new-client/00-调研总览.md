## 关键发现

1. **MaterialClient 采用模块化架构**：`MaterialClient.Common`（共享层）+ 产品特定模块（如 `MaterialClient.Urban`）。新增 `MaterialClient.Recycle` 应遵循同一模式。
2. **ProductCode 体系已建立**：5000（MaterialClient）、5001（MaterialDxlt/城管）、5010（SolidWasteWeightClient）。5020 为新增，需在 BasePlatform 授权体系、运营后台、PublicApi 等环节注册。
3. **授权模式按产品隔离**：仅 5001 使用 JWT；5000/5010 使用现网 `SendAuthLicense`/`DownloadAuth`。5020 推荐沿用 5010 的非 JWT 模式（现网流程不变）。
4. **数据上报模式可插拔**：MaterialClient.Urban 通过 Refit `IUrbanManagementApi` 上报；SolidWaste 使用 `SynchronizationOrderAsync`。Recycle 需要新增一个专用 Refit 接口对接资源化利用厂 API。
5. **已有完整的数据同步基础设施**：称重记录实体、同步状态管理、重试机制、附件体系（`AttachmentFile` + `AttachType`）可复用。
6. **关键证据缺失**：SolidWaste 客户端实现、`SynchronizationOrderAsync` 定义、目标接口文档均需到 [MaterialMonospec](../../../MaterialMonospec/) 中查阅。
